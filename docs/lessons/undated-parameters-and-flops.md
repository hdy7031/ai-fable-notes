每日概念寓言今日寓言：学徒第一次算清“这台机器到底有多重”
城里有一家专门辨认古籍文字的工坊。
工坊里有一种奇怪的筛子。古籍被切成许多小格后，筛子会在纸面上移动，从局部纹理里寻找横线、竖线、转角和其他迹象。
学徒已经跟着师傅学了很久。他知道筛子一次看多大，知道它每次走几格，也知道经过几层以后，上层工匠能够间接利用越来越大的纸面范围。
有一天，掌柜拿来两张设计图。
第一张写着：
输入 3 层，输出 16 层，每个筛子看 \(3\times3\)。

第二张写着：
输入 16 层，输出 64 层，每个筛子仍然看 \(3\times3\)。

学徒扫了一眼：
“两个筛子都是 \(3\times3\)，第二台应该也没贵多少吧？”
掌柜没有回答，只让他去仓库准备制造筛子的金属片。
第一台很快备齐。
到了第二台，学徒却越拿越多。
“奇怪，”他问，“窗口明明还是九格，为什么需要这么多材料？”
师傅拿起其中一个筛子。
“你只看见了它在纸面上覆盖 \(3\times3\)，却忘了纸不是只有一层。”
第一台机器面对的是三层纸面。一个筛子要同时看三层，因此实际上需要：
\[
3\times3\times3
\]
块小金属片。
而且这样的筛子不是一个，而是：
\[
16
\]
个。
第二台面对的却已经是：
\[
16
\]
层特征。
每个新筛子都必须同时看完这 16 层，因此一个筛子需要：
\[
3\times3\times16
\]
块金属片。
这样的筛子还要造：
\[
64
\]
个。
学徒开始在纸上计算，终于发现：
窗口看起来没有变大，机器内部需要保存的东西却增长了很多。

但第二天，他又犯了另一个错误。
掌柜给他两张纸：
一张只有：
\[
32\times32
\]
另一张却有：
\[
1024\times1024
\]
掌柜问：
“同一台筛子处理这两张纸，需要制造两套不同大小的筛子吗？”
学徒想起昨天的教训，小心地说：
“纸大了这么多……应该需要更多金属片吧？”
师傅却摇头。
“筛子还是那个筛子。”
“纸变大，只意味着——”
同一套筛子要被使用更多次。

这一次学徒终于分清了两种“贵”。
一种是：
机器本身要记住多少东西。

另一种是：
机器运行一次，要做多少工作。

后来他进入文字识别研究院，第一次看到有人争论：
“这个模型参数更多，但为什么不一定慢那么多？”

“另一个模型参数不算多，为什么高分辨率输入却特别耗算力？”

他没有再把它们混为一谈。
因为他已经知道：
机器有多重，和机器干一次活有多累，是两个不同的问题。

今天的概念：参数量与计算量
前面我们已经把 CNN 的空间逻辑基本搭起来了：
\[
像素
\rightarrow Tensor
\rightarrow 卷积
\rightarrow Channel
\rightarrow Stride/Padding
\rightarrow 感受野
\rightarrow Pooling
\]
今天补一块极其重要、而且以后读任何 AI 模型都会反复用到的地基：
\[
\boxed{\text{参数量 Parameters 与计算量 Compute}}
\]
以后你会频繁看到：
25M parameters
7B parameters
4 GFLOPs
模型显存占用
推理速度

如果没有把最底层关系弄清，很容易把“模型大”“计算慢”“占显存多”混成一件事。
它们有关，但不是同一个概念。
一、为什么需要区分参数量和计算量？
先从最简单的函数开始。
假设：
\[
y=wx+b
\]
这里机器需要长期保存两个数字：
\[
w,\ b
\]
无论你给它算：
\[
x=1
\]
还是：
\[
x=100
\]
它需要保存的 \(w,b\) 都没有变化。
这就是第一种成本：
模型为了记住自己学到的规则，需要保存多少数字？

这些通过训练学习出来的数字，就叫：
\[
\boxed{\text{Parameters，参数}}
\]
但模型真正运行时，还需要做：
\[
wx+b
\]
也就是乘法和加法。
如果只算一个 \(x\)，工作很少。
如果一次要算一百万个 \(x\)，虽然仍然只有同一个 \(w,b\)，但计算工作会暴涨。
这就是第二种成本：
\[
\boxed{\text{计算量}}
\]
所以今天最重要的第一层区分是：
\[
\boxed{
参数量 = 模型要保存多少学到的数字
}
\]
\[
\boxed{
计算量 = 模型运行时要进行多少数值运算
}
\]
二、先把“参数”彻底弄清楚
我们之前说过，一个卷积核内部其实是一组数字。
例如单通道 \(3\times3\) 卷积核：
\[
\begin{bmatrix}
0.2&-0.1&0.4\\
0.3&0.7&-0.2\\
-0.5&0.1&0.6
\end{bmatrix}
\]
这里有：
\[
9
\]
个数字。
这些数字不是程序员提前规定好的。
训练开始时，它们可能是某些初始化值；随后模型根据训练数据不断调整。
因此它们叫：
可学习参数 Learnable Parameters。
“可学习”不是说这些数字自己会思考，而是：
训练算法允许修改这些数字，让模型的输出逐渐变好。

以后学习反向传播和梯度下降时，我们会正式回答：
到底怎样知道每个数字应该增大还是减小？

今天暂时只需要知道：
卷积核里的权重，就是参数。

三、Bias 又是什么？
我们之前见过：
\[
y=wx+b
\]
其中 \(b\) 叫：
Bias，偏置。
先不用追求严格几何解释，可以把它理解成：
在加权计算结束以后，再允许整体加上一个可学习的调整值。

例如：
\[
y=2x+3
\]
这里：
\[
w=2
\]
是权重，
\[
b=3
\]
是偏置。
两者都是可以学习的参数。
在卷积层里，通常每一个输出通道可以有一个 Bias。
因此如果输出：
\[
64
\]
个 Channel，
通常就有：
\[
64
\]
个 Bias。
四、一个卷积层到底有多少参数？
现在考虑：
Conv2d(    in_channels=3,    out_channels=64,    kernel_size=3)


不要背公式，我们从制造一个卷积核开始。
输入：
\[
3
\]
个 Channel。
也就是：
- R；
- G；
- B。
一个输出卷积核必须同时观察三个输入通道。
每个通道需要：
\[
3\times3=9
\]
个权重。
三个通道：
\[
3\times3\times3=27
\]
所以：
一个完整卷积核需要 27 个权重。

现在我们希望输出：
\[
64
\]
个 Channel。
意味着：
需要 64 组不同的卷积核。

所以：
\[
27\times64=1728
\]
个权重。
再加上：
\[
64
\]
个 Bias：
\[
1728+64=1792
\]
因此：
\[
\boxed{参数量=1792}
\]
五、现在才写参数量公式
我们已经知道每个符号为什么存在了。
设：
\[
C_{in}
\]
表示输入 Channel 数。
\[
C_{out}
\]
表示输出 Channel 数。
\[
K_H,K_W
\]
表示卷积核的高度和宽度。
一个输出 Channel 需要：
\[
C_{in}\times K_H\times K_W
\]
个权重。
总共有：
\[
C_{out}
\]
个输出 Channel。
所以权重数量：
\[
C_{out}C_{in}K_HK_W
\]
如果每个输出 Channel 再有一个 Bias，则：
\[
C_{out}
\]
个 Bias。
最终：
\[
\boxed{
Parameters=
C_{out}C_{in}K_HK_W+C_{out}
}
\]
也可以写成：
\[
\boxed{
C_{out}(C_{in}K_HK_W+1)
}
\]
六、手算一个更真实的卷积层
假设：
Conv2d(    in_channels=64,    out_channels=128,    kernel_size=3)


一个输出卷积核需要：
\[
64\times3\times3
\]
先算：
\[
3\times3=9
\]
所以：
\[
64\times9=576
\]
也就是说：
产生一个输出 Channel，需要 576 个权重。

现在输出：
\[
128
\]
个 Channel。
所以：
\[
576\times128=73728
\]
再加：
\[
128
\]
个 Bias：
\[
73728+128=73856
\]
最终：
\[
\boxed{73856\text{ 个参数}}
\]
注意一个非常重要的现象：
卷积核仍然只是：
\[
3\times3
\]
但参数已经从刚才的：
\[
1792
\]
变成：
\[
73856
\]
为什么？
因为：
\[
C_{in},C_{out}
\]
变大了。
所以不要形成错误直觉：
“卷积核都是 \(3\times3\)，参数应该差不多。”

真正影响卷积参数量的核心因素是：
\[
\boxed{
C_{in}\times C_{out}\times K_H\times K_W
}
\]
七、一个反直觉但极重要的结论
现在假设：
Conv2d(64,128,3)


分别处理：
\[
32\times32
\]
和：
\[
1024\times1024
\]
的特征图。
参数量会不会不同？
答案是：
\[
\boxed{\text{不会}}
\]
仍然是：
\[
73856
\]
为什么？
因为同一个卷积核会在整张图片上重复使用。
这叫：
Weight Sharing，权重共享。
意思就是：
图片左上角使用这一套卷积核参数，右下角仍然使用完全同一套参数。

并不会因为图片有一百万个位置，就制造一百万套卷积核。
这正是 CNN 参数效率高的重要原因之一。
八、但图片变大真的没有代价吗？
当然有。
虽然参数没有增加，但同一个卷积核需要计算更多次。
例如输出只有：
\[
32\times32
\]
那么大约有：
\[
1024
\]
个空间位置需要计算。
如果输出：
\[
1024\times1024
\]
则有：
\[
1,048,576
\]
个位置。
卷积核本身没有变。
但它被使用的次数暴涨了。
所以：
\[
\boxed{\text{输入分辨率不直接改变卷积参数量，却会显著改变计算量}}
\]
这就是寓言里：
筛子没有变多，但同一套筛子要工作更多次。

九、什么叫 FLOPs？
以后论文里经常会看到：
4.1 GFLOPs
15.3 GFLOPs

FLOPs 可以理解为：
Floating Point Operations，浮点运算次数。
浮点数就是计算机中表示小数的一类数字，例如：
\[
0.73,\quad -1.28,\quad 3.14
\]
模型计算里大量数字都是这种形式。
FLOPs 试图描述：
模型完成一次前向计算，大约需要做多少次数值运算。

其中：
\[
1\text{ GFLOP}=10^9
\]
次浮点运算。
不过实际论文和工具对“一次乘加到底算 1 次还是 2 次 FLOP”可能采用不同口径，因此比较模型时最好确认统计方法一致。
现在我们不需要纠结这个工程细节，先掌握数量关系。
十、卷积为什么特别耗计算？
回到：
Conv2d(64,128,3)


假设输出：
\[
128\times56\times56
\]
先只看一个输出数字。
为了产生一个数字，需要读取：
\[
64\times3\times3=576
\]
个输入值。
每个输入值都要和一个权重相乘，再把结果加起来。
也就是说：
生成一个输出值，就需要大约 576 次乘加。

但输出里一共有：
\[
128\times56\times56
\]
个数字。
先算：
\[
56\times56=3136
\]
再：
\[
3136\times128=401408
\]
也就是说需要产生：
\[
401408
\]
个输出值。
每个都需要大约：
\[
576
\]
次乘加。
所以总量大约：
\[
401408\times576
\]
得到约：
\[
231,211,008
\]
也就是：
约 2.31 亿次乘加。

而这只是一层卷积。
十一、现在你可以看到计算量由什么控制
忽略 Bias 和一些细节，卷积的计算量大致与：
\[
\boxed{
H_{out}W_{out}C_{out}C_{in}K_HK_W
}
\]
成正比。
这里“成正比”的意思不是说任何工具都会给出完全相同的 FLOPs 数字，而是：
这些量增大，计算量会按照这个乘法关系增长。

现在逐项看。
如果：
\[
H,W
\]
翻倍，
空间位置数量：
\[
H\times W
\]
大约变成：
\[
4
\]
倍。
所以高分辨率视觉模型很贵。
如果：
\[
C_{in}
\]
翻倍，
计算量约翻倍。
如果：
\[
C_{out}
\]
翻倍，
也约翻倍。
如果卷积核：
\[
3\times3\rightarrow5\times5
\]
面积从：
\[
9\rightarrow25
\]
计算量就明显增加。
十二、参数量和计算量现在可以正式分开了
卷积参数量大约取决于：
\[
\boxed{
C_{in}C_{out}K_HK_W
}
\]
注意这里没有：
\[
H,W
\]
而计算量大约取决于：
\[
\boxed{
HWC_{in}C_{out}K_HK_W
}
\]
多出了：
\[
H\times W
\]
这就是两者最核心的区别之一。
因此完全可能出现：
模型参数不算特别多，但因为一直在高分辨率特征图上计算，所以计算量很大。

也可能出现：
模型参数很多，但某些参数只在很少的位置使用，实际计算模式又不同。

所以以后不要再把：
\[
\text{Parameters}
\]
和：
\[
\text{FLOPs}
\]
当成同一个“模型大小指标”。
十三、为什么 CNN 越深，Channel 经常越来越多？
之前我们见过经典结构：
\[
[64,112,112]
\]
↓
\[
[128,56,56]
\]
↓
\[
[256,28,28]
\]
↓
\[
[512,14,14]
\]
现在终于可以从计算量角度理解这种设计。
网络越深：
\[
H,W
\]
越来越小。
于是我们可以适当增加：
\[
C
\]
也就是特征通道数。
举个粗略例子。
第一阶段：
\[
64\times112\times112
\]
第二阶段：
\[
128\times56\times56
\]
虽然：
\[
64\rightarrow128
\]
通道翻倍，
但：
\[
112^2\rightarrow56^2
\]
空间位置变成原来的四分之一。
因此计算成本并不会因为 Channel 翻倍就直接失控。
这就是很多 CNN 采用：
\[
\boxed{\text{空间越来越小，通道越来越多}}
\]
这种结构的重要原因之一。
十四、参数量还和内存有什么关系？
参数本质上就是大量数字。
假设一个模型有：
\[
100,000,000
\]
也就是 1 亿个参数。
如果每个参数使用：
\[
32\text{ bit}
\]
存储。
32 bit 等于：
\[
4\text{ byte}
\]
所以光保存参数大约需要：
\[
100,000,000\times4
\]
Byte：
\[
400,000,000\text{ Byte}
\]
约：
\[
400\text{ MB}
\]
数量级。
如果是：
\[
7B
\]
也就是：
\[
70亿
\]
参数，
使用 32-bit：
\[
7\times10^9\times4
\]
大约：
\[
28\text{ GB}
\]
仅仅保存权重就已经很大。
这就是为什么大语言模型经常需要：
- FP16；
- BF16；
- INT8；
- INT4。
这些名字先不用深入。
它们的共同思想之一就是：
减少每个参数需要多少 bit 来表示。

例如粗略来看：
32 bit：
\[
4\text{ Byte/参数}
\]
16 bit：
\[
2\text{ Byte/参数}
\]
8 bit：
\[
1\text{ Byte/参数}
\]
4 bit：
\[
0.5\text{ Byte/参数}
\]
所以降低数值精度可以显著减少模型权重的存储需求。
以后学习模型量化时，我们会重新回到这里。
十五、但“参数占 4GB”不等于“只需要 4GB 显存”
这是另一个非常容易踩的坑。
运行神经网络时，GPU 不只需要保存：
模型参数。

还可能需要保存：
- 输入；
- 中间特征；
- 梯度；
- 优化器状态；
- 临时计算结果。
其中“梯度”以后讲反向传播时会详细解释。现在先理解成：
训练时为了知道参数应该怎样调整，需要额外保存的信息。

所以：
\[
\boxed{\text{参数内存只是总显存需求的一部分}}
\]
而且：
训练通常比单纯推理需要更多内存。

推理就是：
模型已经训练好，只负责接收输入并给出输出。

例如 OCR 模型部署到软件里识别图片，就是推理。
十六、参数越多，模型就一定越好吗？
不一定。
参数更多意味着：
模型拥有更多可以调整的数字，通常具有更大的表示能力。

但它也可能：
- 更难训练；
- 占用更多存储；
- 需要更多数据；
- 更容易出现过拟合；
- 部署成本更高。
这里第一次出现：
过拟合 Overfitting。
先给最简单的理解：
模型把训练数据记得太死，却没有真正学到能够推广到新数据的规律。

比如学生把练习册答案全部背下来，原题全会，一换数字就不会。
这就是一种很粗略的过拟合直觉。
以后我们会专门学习它。
十七、这和你以后做 OCR 有什么直接关系？
假设有两个 OCR Backbone。
模型 A：
\[
5M\ Parameters
\]
模型 B：
\[
50M\ Parameters
\]
不能仅凭：
\[
50M>5M
\]
就认为 B 一定更好。
实际工程还需要看：
\[
准确率
\]
\[
FLOPs
\]
\[
显存
\]
\[
推理延迟
\]
\[
输入分辨率
\]
\[
部署设备
\]
例如工业 OCR 可能部署在边缘设备上。
“边缘设备”就是：
靠近数据产生现场、计算能力通常比大型服务器有限的设备，例如工业电脑、嵌入式设备等。

这时一个准确率只高一点、却慢五倍的大模型，未必是更好的工程选择。
所以以后做模型选择，不能只问：
“谁准确率最高？”

而应该开始建立：
\[
\boxed{\text{精度—参数量—计算量—内存—速度}}
\]
之间的整体权衡意识。
这已经是从“学习模型”迈向“做工程”的重要一步。
十八、这套思想也直接通向大语言模型
以后看到：
7B、32B、70B

其中：
\[
B=Billion=10^9
\]
7B 就是大约：
\[
70亿参数。
\]
这些数字主要描述的是：
模型包含多少可学习参数。

但 70B 模型一次回答到底要算多少东西，并不能只看：
\[
70B
\]
还会受到：
- 输入长度；
- 输出长度；
- 模型结构；
- 数值精度；
- 硬件；
- 推理算法
等因素影响。
因此今天在一个小小的：
\[
3\times3
\]
CNN 卷积里学到的区别，会一路延伸到大模型部署。
回到工坊里的筛子
寓言中的对应关系现在可以完整拆开：
寓言	神经网络中的含义
金属片	可学习权重
一套筛子	一个卷积核
三层纸面	3 个输入 Channel
16 层特征	16 个输入 Channel
制造 64 套筛子	64 个输出 Channel
制造需要多少材料	参数量
筛子在纸上使用多少次	计算量
大纸张	更大的 \(H,W\)
同一筛子反复使用	权重共享
筛子没变但工作更多	参数量不变、计算量增加


这个隐喻最重要的成立点是：
参数描述“模型保存了什么”，计算量描述“模型运行时做多少工作”。

但不能机械理解为每个参数在硬件里就是一块独立金属片。真实 GPU 会进行高度并行的矩阵运算，而且运行速度不仅由 FLOPs 决定，还受到内存带宽、并行度、硬件利用率等因素影响。
所以：
\[
FLOPs低
\]
也不能严格推出：
\[
运行时间一定短。
\]
它更多是一个非常有用的理论计算成本指标。
今天真正需要记住的 5 个点
1. 参数是模型通过训练学到并需要保存的数字。
卷积层参数量核心关系：
\[
\boxed{
C_{out}C_{in}K_HK_W
}
\]
Bias 再额外增加约 \(C_{out}\) 个参数。
2. 参数量和计算量不是一回事。
参数量回答：
模型要保存多少学到的数字？

计算量回答：
模型运行一次大概要做多少数值运算？

3. 卷积有权重共享。
同一个卷积核在整张图片不同位置重复使用，因此：
\[
H,W
\]
变大不会让卷积层拥有更多参数。
但是会让它：
计算更多次。

4. 卷积计算量大致与下面这些量的乘积相关：
\[
\boxed{
HWC_{in}C_{out}K_HK_W
}
\]
所以高分辨率、高 Channel 数和大 Kernel 都可能显著增加计算成本。
5. “模型大”不是一个足够精确的说法。
以后看到一个模型，至少要区分：
\[
参数量、计算量、内存占用、实际运行速度
\]
它们相关，但绝不是同一个指标。
下一步知识网络
现在 CNN 的结构地基已经相当完整：
\[
像素
\rightarrow Tensor/Shape
\rightarrow Channel
\rightarrow 卷积
\rightarrow Stride/Padding
\rightarrow 感受野
\rightarrow Pooling
\rightarrow
\boxed{参数量/计算量}
\]
下一步最自然的前置补充是 ReLU 与“非线性”。我们已经多次写过：
\[
Conv\rightarrow ReLU\rightarrow Pool
\]
但一直只说“ReLU 引入非线性”。现在应该真正解释：什么叫线性、为什么很多层线性变换叠起来仍然等价于一层，以及为什么没有非线性，深度神经网络的“深”会失去很大一部分意义。
紧接着最自然的后续概念就是把目前所有零件第一次组装成完整 CNN：
\[
输入
\rightarrow Conv
\rightarrow ReLU
\rightarrow Pool
\rightarrow Conv
\rightarrow ReLU
\rightarrow Pool
\rightarrow 输出
\]
到那一步，我们可以对一个真正的小网络从头算到尾：每层 Shape 怎么变、参数有多少、感受野多大、特征在做什么。这会成为继续进入 OCR 主干网络和完整文字识别流程前最关键的一次知识收束。
