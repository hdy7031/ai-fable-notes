# 今日寓言：巡逻队的步子

山城的巡逻队用三格宽的木尺检查城墙裂缝。起初，他们每次移动一格，能留下很多细致记录，却要忙到深夜。队长让他们每次移动两格，效率立刻提高，但记录少了许多。更糟糕的是，靠城墙两端的石块无法像中间那样被观察：木尺必须整个放在墙面上。

工匠于是沿墙边铺上几块写着“零”的临时砖。巡逻员能把木尺停在原本到不了的位置，给边缘附近也算一个结果。

有学徒不解：“这些砖是假的，难道不会影响结果？”工匠说：“当然会。我们需要明确补的是什么、补多少。缩短步子会增加观察位置，跨大步会减少观察位置；补砖能改变边缘的计算范围，却不能创造真实信息。”

老队长终于把每天能产生多少记录归结为三个问题：木尺多宽、每次移动多远、两端补了多少格。

# 概念揭示：Stride 与 Padding

## 一、解决什么问题
卷积核在输入图像上滑动时，需要决定一次滑动多远，以及怎样处理边界。这两个设置影响输出的空间大小和计算量。步幅 Stride 规定移动距离；填充 Padding 在输入边界添加额外数值，常见的是补零。

## 二、前置概念
**卷积核**是局部计算的小窗口。**输入长度**是某方向有多少个位置。**输出长度**是滑动窗口总共能停靠多少次。**向下取整**指去掉小数部分，例如 2.8 向下取整得到 2。

## 三、定义和公式
先看一维情形。令 \(L\) 为输入长度，\(K\) 为核宽度，\(P\) 为每侧填充格数，\(S\) 为每步滑动格数。我们从最左边开始，把长度为 \(K\) 的窗口放在补充后的序列上，只有窗口完整落在范围内时才计算结果，因此输出位置数为
\[
L_{\text{out}}=\left\lfloor\frac{L+2P-K}{S}\right\rfloor+1.
\]
这里 \(\lfloor\cdot\rfloor\) 表示向下取整，末尾的 \(+1\) 是把最初那次放置也算进去。二维图像的高与宽可以分别按同样原则计算。

## 四、手算
输入为 \([1,2,3,4,5]\)，核宽 \(K=3\)，不填充 \(P=0\)。步幅为 1 时，可以覆盖 \([1,2,3]\)、\([2,3,4]\)、\([3,4,5]\)，共 3 个位置。代入 \(L=5,K=3,S=1\)：
\[
\lfloor(5-3)/1\rfloor+1=3.
\]
步幅改为 2，则覆盖 \([1,2,3]\) 和 \([3,4,5]\)，只有 2 个结果。若两侧各填充一个零且步幅恢复为 1，补充后的序列有 7 格，可得到 \(7-3+1=5\) 个结果。

## 五、AI/OCR 的意义
CNN 可通过较大步幅减少计算和空间分辨率，但 OCR 的细小笔画可能因此丢失。适当填充可帮助保留边缘位置的响应，不过补零不等于真实像素。实际框架中的 same padding 有特定尺寸约定，不能简单理解成任何情况下都补一圈零。

## 六、寓言映射
木尺是卷积核；跨步是 stride；边缘临时砖是 padding；巡逻记录数量对应输出位置。局限：真实卷积是加权乘加，临时砖只是为输入补数值，不能提升原始图像信息量。

## 七、今天真正记住
1. Stride 决定滑动间隔。
2. Padding 决定边缘添加多少值。
3. 输入尺寸、核大小、步幅与填充共同决定输出尺寸。
4. 更大步幅通常更省计算，但更容易丢空间细节。
5. CNN 调试时要会逐层检查张量形状。
