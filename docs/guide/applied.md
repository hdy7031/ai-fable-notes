## 四个阶段如何连接

推荐依次学习“应用工作流 → 现代视觉 → 大语言模型与多模态 → Agent 与工程系统”。先学会定义问题、控制数据与验证实验，再选择技术，最后把模型接入可观察、可维护的系统。

| 阶段 | 要解决的问题 | 主要知识与实践产物 |
| --- | --- | --- |
| [AI 应用工作流](../generated/stages/applied-workflow.md) | 如何判断一个模型是否解决了实际问题？ | 问题定义与基线、数据质量与泄漏、迁移学习与微调、指标与错误分析、消融与复现。整理任务说明、固定数据划分和实验记录。 |
| [现代视觉技术](../generated/stages/modern-vision.md) | 需要位置、像素边界，还是相似图片？ | 目标检测与 YOLO、图像分割、图像向量与检索、CLIP 与对比学习。比较输入、输出、标注成本与失败案例。 |
| [大语言模型与多模态](../generated/stages/llm-multimodal.md) | 模型如何使用语言、外部知识与图像？ | Token 与嵌入、预训练与指令微调、RAG、视觉语言模型、幻觉与评估。追踪查询、检索、上下文与回答的数据流。 |
| [Agent 与工程系统](../generated/stages/agent-systems.md) | 如何让模型可靠地调用工具并提供服务？ | 工具调用与工作流、状态与编排、模型导出与服务化、延迟、吞吐与量化。记录工具输入输出、状态变化、服务指标和故障处理。 |

各阶段共享同一套验证方法。检测与分割依赖前面的数据和指标设计；向量检索与对比学习帮助理解跨模态表示，随后可以把检索能力用于 RAG。学习 Agent 时，再将模型输出变成工具操作，并检查状态、失败重试和服务边界。

## 每篇文章怎样学

后续文章继续采用“原创寓言 + 原理解释”。寓言用角色、冲突和转折提出问题，原理部分会解释对应关系与比喻边界。教学重点围绕实际问题、数据流、技术选型、案例分析、常见错误和工程验证展开；公式只在有助于推理或计算时加入，并解释符号含义。

阅读时可以按以下顺序做一轮小实验：

1. 写清输入、预期输出、使用场景和约束，并确定一个可运行的简单基线。
2. 固定训练、验证和测试数据。检查重复样本、来源混用、标注口径与数据泄漏，保留测试集供最终评价。
3. 画出从原始输入到最终结果的数据流，记录预处理、模型、后处理以及工具接口。
4. 每次改变一个关键因素，在相同数据和评价口径下与基线比较。保存配置、数据版本、随机种子、代码版本和运行环境。
5. 检查有代表性的成功与失败案例，区分数据、模型、接口和评估方法造成的错误。结论要对应实际证据，注明尚未验证的部分。

例如研究文档中的字段提取时，可以先固定一批有人工标注的验证文档，明确最终字段如何计分，再分别检查图像预处理、定位、识别与字段解析。比较视觉语言模型或 RAG 方案时，继续使用同一评价口径，同时记录耗时与资源消耗。这样能说明改动改善了哪个环节，以及仍有哪些限制。

## 学习节奏与路线选择

先完成一个小规模、可复现的闭环，再扩大模型或数据规模。工程实验可以使用本地模型、公开工具和已有数据；学习不要求购买 API。

在首页或学习路线中主动选择路线，浏览器会记住选择。读完基础主线后，首页会提示可以进入应用进阶，由你决定何时切换。临时查阅概率统计或 OCR 课程不会改变这个选择。
